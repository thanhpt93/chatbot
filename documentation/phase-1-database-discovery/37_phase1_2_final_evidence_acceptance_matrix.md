## 2. Strict Definitions of Validation Levels & Allowed Final Statuses

### 2.1 Validation Levels
- **`DESIGNED`**: Architecture or contract is documented in Phase 1.2 / 1.2.1 / 1.2.2 specifications.
- **`STATICALLY VALIDATED`**: SQL/Cypher syntax, table names, column names, data types, and cross-document references have been programmatically verified against `schema_inventory.json` via [`scripts/phase1_2_2/run_all.py`](file:///C:/Project/chatbot/scripts/phase1_2_2/run_all.py) and [`scripts/phase1_2_1/validate_phase1_2_1.py`](file:///C:/Project/chatbot/scripts/phase1_2_1/validate_phase1_2_1.py).
- **`EXECUTED`**: Discovery/profiling SQL, read-only PostgreSQL 18.6 query validation (`127.0.0.1:5433`), or Python validation scripts have actually been executed against the PostgreSQL 18.6 catalog/data or project markdown artifacts.
- **`EXECUTED (SYNTHETIC FIXTURE)`**: SQL queries, ETL reconciliation patterns (`R-1`–`R-7`), and graph traversal semantics (`Q01`, `Q05`, `Q08`, `Q11`, `Q14`, `SEC-01`–`SEC-25`, Attendance `Cases A–E`) have been executed against the deterministic multi-tenant SQLite + Python Graph simulation fixture (`tests/phase1_2_2/`), without claiming live Neo4j server execution.
- **`RESULT VALIDATED`**: Execution results (`data_profile.json`, `phase1_2_2_consistency_report.json`) have been checked against expected cardinality, nullability, match rates, and expected test outputs.
- **`SECURITY TESTED`**: Negative security and cross-tenant isolation tests have been executed at runtime against a live database/backend instance (`NOT EXECUTED` on live Neo4j; `EXECUTED (SYNTHETIC FIXTURE)` in `scripts/phase1_2_2/validate_tenant_security.py`).
- **`STAKEHOLDER APPROVED`**: Business or governance decision has explicit stakeholder sign-off.

### 2.2 Allowed Final Acceptance Statuses
- **`PASS`**: Fully verified with `EXECUTED` + `RESULT VALIDATED` (or `STATICALLY VALIDATED` where static architecture consistency is the criterion) and zero contradictions.
- **`PASS WITH CONDITIONS`**: Technically consistent, statically validated, and verified on synthetic fixtures (`8/8` Phase 1.2.2 validators + `13/13` Phase 1.2.1 checks pass), with live Neo4j runtime execution or stakeholder confirmation tracked as explicit Phase 2 entry conditions.
- **`FAIL`**: Contains unresolved technical contradictions or defects (`0` items in Phase 1.2.2).
- **`NOT VERIFIED`**: Required source artifact (such as external C#/.NET backend application code in `AC-05B`) is outside the current workspace (`MISSING EVIDENCE`).
- **`NOT EXECUTED`**: Designed, statically validated, and verified on synthetic fixtures, but target live runtime environment (Neo4j 5.x / Vector DB / Live Backend API) is not provisioned in Phase 1.2.2 (`AC-15`, `AC-17`).
- **`BLOCKED`**: Cannot be implemented in MVP until a source schema defect or stakeholder decision is resolved (`:WorkflowTemplate` `ND-11` / `[:USES_TEMPLATE]` `RM-19` in `AC-08`).
- **`NOT APPLICABLE`**: Out of scope for the current architecture.
